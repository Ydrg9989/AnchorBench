# AnchorBench: Data Generation Pipeline

## Overview

The data generation pipeline produces benchmark datasets for measuring anchoring bias in LLMs. Each dataset contains **ItemSpecs** (ground-truth records) and **PromptViews** (rendered prompts), organized by suite, domain, difficulty, and condition.

## Pipeline Stages

```
1. ItemSpec Generation   →  ground-truth records (theta, evidence, anchors, gold answer)
2. Prompt Rendering      →  concrete prompts per condition (5 per ItemSpec)
3. Serialization         →  itemspecs.jsonl, promptviews.jsonl, manifest.json
```

### Stage 1: ItemSpec Generation

**Module:** `src/anchorbench_v1/itemspec_gen.py`

Each ItemSpec is generated by iterating over a stratified grid:

```
for domain in DOMAIN_IDS:           # 6 domains
    for difficulty in [easy, hard]:  # 2 levels
        for offset in [15, 25, 40]: # 3 anchor distances
            for i in range(n_per_cell):
                → create one ItemSpec
```

Key computations:
- **theta** (latent signal): drawn uniformly from [30, 70]
- **anchor_low/high**: `max(0, theta - offset)` / `min(100, theta + offset)`
- **evidence**: 5 ratings drawn around theta with controlled noise
  - Easy: sigma=8, all visible
  - Hard: sigma=15, 2 missing, 1 conflicting
- **y_star_evidence** (gold answer): `round(mean(visible evidence values))`

Suite-specific additions:
- **History**: subset search for plausible pressure; same-domain warmup cases
- **ICL**: 3 neutral demo examples pre-generated and stored in tags
- **RAG**: corpus metadata (3-doc mini-corpus built at render time)
- **Tool**: available tool schemas

### Stage 2: Prompt Rendering

**Modules:** `src/anchorbench_v1/suites/{external,history,icl,rag,tool}.py`

Each ItemSpec produces exactly **5 PromptViews**, one per condition:

| Condition        | Anchor Relevance | Anchor Direction |
|------------------|------------------|------------------|
| control          | none             | —                |
| irrelevant_low   | irrelevant       | low              |
| irrelevant_high  | irrelevant       | high             |
| plausible_low    | plausible        | low              |
| plausible_high   | plausible        | high             |

The anchor is injected through a suite-specific channel:
- **External**: sentence before the question
- **History**: warmup case (irrelevant) or partial-evidence subset (plausible)
- **ICL**: demo header metadata
- **RAG**: anchor document in the retrieved corpus
- **Tool**: field in the tool output JSON

The **benchmark invariant** is that across all 5 conditions for a given item, everything except the anchor-bearing component is identical.

### Stage 3: Serialization

**Module:** `src/anchorbench_v1/schema.py`

Output files (per suite):
- `itemspecs.jsonl` — one JSON object per line, one ItemSpec per item
- `promptviews.jsonl` — one JSON object per line, one PromptView per condition
- `manifest.json` — generation metadata (version, seed, counts, file paths)

## Entry Point

```bash
# Generate all 5 suites (pilot size, seed 42):
bash scripts/generate_all.sh pilot 42

# Generate a single suite:
PYTHONPATH=src python -m anchorbench_v1.generate \
    --suites external --size pilot --seed 42 \
    --out_dir datasets/anchorbench_external_pilot/
```

## Validation

```bash
# Validate all suites:
bash scripts/validate_all.sh pilot

# Validate a single suite:
PYTHONPATH=src python -m anchorbench_v1.validate \
    --data_dir datasets/anchorbench_external_pilot/
```

## Deterministic Regeneration

Generation is fully deterministic given the same seed. Each suite uses a different seed offset to ensure independence:

| Suite    | Seed Offset |
|----------|-------------|
| External | +0          |
| History  | +0          |
| RAG      | +2000       |
| Tool     | +3000       |
| ICL      | +4000       |

## Domain Configuration

All templates, evidence labels, and anchor preambles are defined in `src/anchorbench_v1/domains.py`. The six domains are:

1. `pricing_wtp` — Willingness-to-Pay
2. `operations_time` — Operational Efficiency
3. `transportation_logistics` — Logistics Reliability
4. `resource_consumption` — Resource Efficiency
5. `market_demographics` — Market Adoption
6. `legal_policy` — Regulatory Compliance
